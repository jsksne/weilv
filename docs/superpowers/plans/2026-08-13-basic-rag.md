# Basic RAG Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the Stage 3 Basic RAG minimum end-to-end loop over the reviewed knowledge and micro-task indices.

**Architecture:** Add one thin orchestration module that adapts the Stage 3 request to the frozen Stage 1 safety contract, calls the existing Stage 2 retrieval/model boundaries, and copies the selected task from Elasticsearch. Extend existing helpers only where Elasticsearch needs richer filters or task-ID deduplication.

**Tech Stack:** Python 3.12, dataclasses, Elasticsearch 8.19, DashScope, pytest.

## Global Constraints

- Input safety runs before retrieval or model calls.
- `unstable_environment` maps to `unstable_reading_or_screen` only in the structured `study_space` context.
- `sleep_being_crowded` maps to `sleep_displaced_by_study` in the Stage 3 adapter.
- Do not modify Safety Rules v0.1, reviewed knowledge, or reviewed micro-tasks.
- Task order is metadata filter, safety filter, then reranker.
- The selected task is copied from `micro_tasks_v1`; the LLM only writes a short explanation.
- One query embedding is reused by knowledge and task vector search.
- Stage 4 remains out of scope.
