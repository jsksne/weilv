## 2. 产品目标与成功标准

目标用户：小学高年级、初中、高中学生；主要在课间、学习间隙、放学后或睡前使用。

产品定位：低负担、可商量、能逐步适应用户的个性化健康微行动助手。

本轮核心体验：

> 表达当前状态 → 获得一件合适的小事 → 不合适时说明原因 → 调整建议 → 开始执行 → 完成或放下 → 反馈是否合适 → 后续推荐使用反馈。

成功标准：

1. 用户能自然追问，不必重复上一轮内容。
2. AI 给出的任务可以直接执行，并出现在一致的今日记录中。
3. 调整当前状态不会抹掉正在做或已经完成的事情。
4. 界面准确区分保存中、成功和失败；相关页面不持续展示过期状态。
5. 用户能表达推荐为什么不合适；任务完成与任务是否合适分别记录。
6. 首页和回答首先帮助用户决定下一步，详细解释按需查看。

保留现有技术栈、视觉风格和四个主页面。范围限于本 spec 的功能衔接与体验调整，不开展全站重写。

## 3. 交付范围与顺序

| 阶段 | 必须交付的内容 | 依赖 |
|---|---|---|
| A：行动闭环 | F1 连续对话、F2 建议转行动、F3 进行中界面、F4 今日状态保留与同步 | 先明确任务记录与会话数据契约 |
| B：推荐可调整 | F5 不合适原因、F6 完成后轻反馈、F7 首页与当前状态、F8 回答和等待体验 | A |
| C：持续理解用户 | F9 简化首次引导、F10 可纠正记忆、F11 有行动出口的周报 | B；相应数据能力可用 |

A、B 是优先落地的完整首批范围；C 是确定方向的后续批次。不能用实现 C 中较容易的文案修改代替 A、B 的核心能力。各阶段分别说明完成项和缺口，不把部分完成写成整份 spec 已完成。

暂缓候选，不纳入本轮实现：

- “今天先少一点”：减少未开始任务，保留已完成成果。
- “再做一次”：从近期适合自己的任务中再次选择，并重新检查当前适用条件。
- 用户主动开启的提醒。

不在范围内：积分商城、排行榜、连续打卡惩罚、社交社区、家长实时监督面板、复杂健康记录系统、复杂考试模式、全新账号平台。

## 4. 功能设计

### F1. 连续对话与自然追问

已知基准：前端仅持有一组 question/reply，每次提交覆盖；请求没有显式携带本轮对话历史。这不等于后端没有个人记忆，两者需要区分。

目标行为：

- 用按顺序排列的消息展示当前会话；新问题追加，旧问答保留。
- 请求携带受现有模型上下文预算约束的最近会话内容，或复用后端已有会话能力。必须实际传到生成/理解环节，不能仅把气泡留在页面上。
- 支持“再简单一点”“我现在不方便起身”“刚才那个适合在教室做吗”等依赖上文的表达。
- 指代有歧义时，先简短澄清。不得靠猜测改变任务。
- 单个会话同一时刻只运行一个回答请求；等待时允许编辑下一问。
- 提供“新对话”入口。当前会话在四个主页面间切换时保留；首版不新增历史会话列表、跨设备同步或浏览器刷新后的会话恢复。
- 新对话清除会话上下文，不删除今日任务、用户画像或已授权的长期记忆。
- 对话文本不得仅因为进入上下文就自动转为长期记忆；沿用项目的授权与记忆提取边界。

验收：连续发送两问，第一轮仍可见，第二次请求含必要上文；切到今日再回来会话保留；新对话不携带上一会话消息。

### F2. AI 建议直接转为行动

已知基准：交付提交的建议按钮被禁用。本地中断修复已加入“定位今日已有任务”，但建议不在今日清单时仅给提示。

目标行为：

- 建议卡提供主动作“开始这件事”和次动作“加入今日”。
- 今日已有同一项未结束任务：定位/打开该项，不重复添加；正在执行则显示“继续”。
- 今日尚无该任务：通过正式数据链路加入今日，再开始或保留待开始状态。
- 今日同一任务已完成：显示“今天已完成”。首版不顺便实现重复执行；“再做一次”留给后续批次。
- 保存中显示进行状态，阻止重复提交；失败保留建议卡并提供重试，不冒充已加入。
- AI 对话卡、今日卡和执行界面引用同一执行记录；状态在这些入口之间同步。
- 无可执行安全任务时不显示可开始按钮，沿用实际分流结果。

数据要求：taskId 是任务定义标识，不能当成单次执行记录标识。保留真实 recommendationId 与任务、用户、日期的关联；若现有接口不足，补充最小正式接口。不能捏造推荐 ID，也不能将同一个推荐 ID 任意绑定到多项任务。

验收：对话推荐一个今日没有的合法任务，加入并开始后今日可见；再次点击同一建议不重复添加；完成后两个入口状态一致。

### F3. 任务进行中界面

采用现有页面中的任务详情层/面板，复用今日和 AI 两个入口，不增加一个顶层主页面。

内容仅包含：任务名称、正式步骤、必要说明，以及“完成了 / 做了一部分 / 先放下”。

- 状态语义：待开始 → 进行中 → 已完成或部分完成；“先放下”保留可恢复状态，不记作已完成或失败。
- 关闭详情层不等于结束任务，回到卡片仍可继续。
- 明确适合计时的任务可提供可选计时。任务无明确计时定义时不自动添加倒计时。
- 计时结束不自动完成；由用户确认实际执行情况。
- 切换主页面或刷新后，依照已保存记录恢复任务状态。
- 先复用已有状态和事件语义；确需补充“暂放”时，明确存储与恢复行为，不与“跳过”混为一谈。

验收：开始 → 关闭面板 → 再次打开可以继续；部分完成与全部完成保持区别；计时到点不会虚增完成记录。

### F4. 今日状态保留、保存反馈与页面同步

已知基准：Today model 刷新会重置前端任务交互状态；已提交版任务动作不等待上报结果。本地修改已开始处理动作保存结果。

- 已完成、部分完成和进行中的任务不因心情/时间变化消失或回到待开始。
- 推荐调整只作用于未开始的候选任务；替换时使用稳定记录身份，不能按数组槽位把旧状态套给新任务。
- 每个任务动作有提交中、成功、失败反馈。失败后可重试，不显示成功计数。
- 今日数据加载应读回当天已保存的任务/动作状态，而不是每次刷新仅生成一批全新推荐。
- 新的一天使用新的当天列表，不把昨日执行状态套给今日；日期口径复用项目既有业务约定。
- 保存成功后更新依赖该事件的今日计数、画像概览、周报数据。采用局部刷新或数据失效重取，避免卸载整站导致会话丢失。
- 周报读取失败不撤销已成功保存的任务；说明统计暂未更新并允许重试。
- 心情/时间更新期间显示“正在调整未开始的任务”；失败说明推荐未更新并保留原任务。
- 若用户选择的状态与已生效推荐条件不同，明确显示本次调整未生效，避免用新选项暗示旧推荐已适配。

验收：完成一项后改变可用时间，已完成项及记录保留；保存失败不增加成功数量；成功后周报/概览刷新；刷新页面能恢复当天进度。

### F5. “现在不适合”：带原因的调整

任务卡和建议卡提供“现在不适合”，展开以下可选原因：

| 用户选择 | 本次处理 | 记忆边界 |
|---|---|---|
| 时间不够 | 必要时追问可用分钟数，重新选择符合时长的任务 | 当前约束，不推断长期偏好 |
| 场合不方便 | 必要时澄清具体限制，如不方便起身，再筛选 | 当前场景，不自动长期保存 |
| 今天不想做这类 | 当前推荐轮次避开该类候选 | 不推断永久讨厌该类 |
| 今天已经做过类似活动 | 记录用户自报的当日活动，并避免重复推荐类似活动 | 不伪造已完成的应用内任务记录 |

- 原因选择不成为强制问卷；保留直接返回和普通换一个。
- 正在做的任务先由用户明确“先放下”或结束，推荐更新不自动中断。
- 更换后简短解释实际变化，例如“换成了不需要起身的一项”。
- 必须重新走项目现有适用性与安全筛选；没有合适候选时如实说明，不强行凑一个。
- 任务正文和正式时长来自已审核任务。不能把一个正式 5 分钟任务随意改写为 1 分钟来满足要求。

验收：用户说明不方便起身，下一任务符合该约束；无候选时不返回违背条件的任务；当日限制没有变成长久偏好。

### F6. 完成后一次轻反馈

- 完成或部分完成保存成功后，可选展示“这次感觉怎么样？”与“合适 / 有点费劲 / 没什么帮助”。
- 不回答也可以离开，不影响完成记录，不反复追问。
- completionStatus 与 suitabilityFeedback 分开保存，绑定同一真实执行记录。
- 用户可以修改本次反馈；修改替换该条评价，不累加成多次完成。
- 反馈保存失败只影响反馈，不撤销完成状态；提供重试。
- 已授权的反馈可在现有个性化排序中使用：先保证候选安全适用，再做有限偏好调整。
- “没什么帮助”是用户主观体验，不解释为医学无效；一次反馈不概括为永久规律。
- 只有推荐链路实际读取并应用相应反馈时，才显示“这次参考了你的反馈”等说明。

验收：完成且评价“有点费劲”同时成立；跳过评价仍算完成；修改评价不增加任务数；后续推荐可追溯是否使用了反馈。

### F7. 首页与当前状态

- 首页主要顺序：简短问候 → 当前状态 → 一件优先推荐的任务 → 其他备选。
- 已有进行中任务时，“继续这件事”占优先位置，不继续催用户开始更多事项。
- 已完成成果保留；不要把部分完成伪装成全部完成。可以鼓励投入，但文字与统计含义必须一致。
- 心情、时间、场景可以独立修改；不强迫用户每日填完整问卷。
- 可用时间加入“3 分钟 / 5 分钟”，保留现有较长选项供需要者使用，短选项靠前。选择 3 分钟时必须使用正式时长不超过 3 分钟的合适任务。
- 必要的场景输入采用“在教室 / 在家 / 其他”或现有等价选项；用户未提供时保留未知，不把地点自行等同于可以活动。
- 默认选中项不得冒充用户当日实际输入；未知状态与主动选择在数据上可区分。
- 场景选项本身不能替代具体约束；“不方便起身”等说明优先进入本次适用性判断。

验收：首屏有明确优先动作；进行中任务优先；短时间选项影响实际筛选；修改状态不重置已有成果。

### F8. 回答呈现与等待体验

- 默认内容顺序：直接回应 → 可执行建议/必要澄清 → 任务动作 → 可展开的依据和过程。
- 安全分流和必须立即知道的说明不得折叠隐藏；详细技术阶段不抢占正常回答的主要位置。
- 快捷追问根据当前回答提供少量选项，如“换一个”“我只有几分钟”；触发后走真实对话请求。
- 回答等待时允许编辑草稿；发送按钮等待当前请求结束再启用。
- 提供“停止等待”。停止后保留提问和已显示内容，明确标识中断；新消息不被旧请求迟到结果覆盖。
- 若后端暂不支持真正取消执行，只承诺停止本轮等待/显示更新，不能声称后端计算已停止。用户主动停止不得触发非流式自动重试。
- 出错时在对应消息附近显示简短错误与重试，保留问题；重试同一轮不重复追加用户消息。
- 新消息默认跟随；用户主动上滑后不抢滚动，提供回到最新。
- 手机输入框保持稳定可用；不随意推翻既有单行布局修复。输入标签、选中态和必要触控区域保留。

验收：正常回答无需展开过程就能理解下一步；停止后迟到结果不污染后续消息；重试不重复提问；上滑阅读不会被持续拉回底部。

### F9. 简化首次引导

- 首次先收集当前后端生成合法推荐所必需的信息，例如目标学段；其他必需条件沿用正式契约。
- 长期偏好、常用时段等可稍后补充；不能只从 UI 删除字段，却继续向后端发送假的默认答案。
- 记忆授权单独说明实际用途，保持可选择性；拒绝授权不应被伪装为已开启。
- 若现有项目要求特定必填或安全字段，保留该要求，调整呈现顺序，不绕过约束。
- 提供“先看看”；缺少必要画像时可以浏览，但需要正式推荐时就地补充，不假装已经个性化。
- 不在首次引导结束后强制紧接一轮全功能教程。保留用户主动打开教程的入口。
- 学段与产品目标一致：小学高年级、初中、高中。

验收：必要信息完成后能尽早获得推荐；跳过/拒绝授权语义真实；无强制双重教程；缺失字段不会被默认值冒充。

### F10. 可纠正的记忆

- 在已有记忆卡上支持“修改 / 不再适用”，保留删除入口，不新增复杂管理页面。
- 保存修改后，画像展示与后续检索一致；失效记忆不再参与推荐。
- 短期考试、近期作息等与长期偏好区分。首版复用已有时间/有效性字段；确实缺失时补最少必要字段与读取过滤逻辑。
- 用户明确说“只是最近”时，不写成永久结论；没有明确期限时不擅自制造到期日期。
- 修改失败保留原内容及编辑草稿，说明未保存；不假装更正成功。
- 尊重现有记忆授权、删除与持久化规则。

验收：修改后下一次画像读取返回新值；不再适用的记忆被排除；暂时情况不变成无期限长期偏好。

### F11. 周报提供下一步

- 主要呈现一个真实发现、一项可选择的后续调整；已有统计作为支撑内容。
- 优先使用可核对的记录，例如“本周完成的任务里，短任务占比较多”，不要把相关性说成健康改善或因果结论。
- 数据不足时说明仍在积累，并给出已有记录；不生成虚构趋势。
- 提供“下次优先短任务”等与发现相关的明确选择，点击后按现有授权和偏好契约保存。
- 已保存才确认生效；下一次推荐在安全适用候选内读取该偏好。
- 不用排名、惩罚和负面评价催促完成。

验收：发现能对应真实记录；不足时无虚构规律；调整偏好可读回，并影响适用候选内的后续选择。

## 5. 实现连接点与数据约定

以下是当前已知的修改入口，不要求按文件机械拆分，也不表示只改前端即可完成：

| 区域 | 已知入口 |
|---|---|
| 应用编排、今日刷新、动作上报 | `frontend/src/App.vue` |

## 6. 最小验收与工作方式

用户明确要求：本轮不开展浏览器验收、截图矩阵、全站审计或重复的繁琐验证。实施时以受影响行为的针对性测试和必要类型/构建检查为主；不把“未做浏览器验证”扩张为额外工作。

每次检查应回答一个实际问题；检查发现失败后应能直接决定修什么。不要为样式小改写镜像测试，也不要无变化地反复全量运行。

核心行为验收可使用项目现有单元/集成测试，通过可控数据覆盖：

| 场景 | 必须成立 |
|---|---|
| 连续两问 | 第一轮可见，第二轮请求包含必要上下文 |
| 停止后继续提问 | 旧结果不覆盖新消息；停止不触发自动备用请求 |
| AI 任务加入今日 | 真实保存、无重复项、两个入口同步 |
| 完成时服务失败 | 不误报成功；重试不重复计数 |
| 完成后改变心情/时间 | 保留已完成与进行中记录，只调整未开始候选 |
| 页面刷新 | 当天已保存进度可恢复 |
| 推荐不适合 | 具体原因进入实际筛选，临时限制不变长期偏好 |
| 完成后评价 | 评价与完成状态独立，修改评价不增加完成数 |
| 画像/周报更新失败 | 已保存任务不回滚；相关数据能重试刷新 |
| 记忆更正与周报偏好 | 保存可读回，后续推荐使用正确且有效的数据 |

交付时提供：实际修改摘要、已完成阶段、检查结果、尚未完成项及影响，以及第 8 节要求的 GitHub 推送结果。用户未要求额外执行生产部署，不额外启动部署流程。
